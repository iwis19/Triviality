# Bounds and failure behavior

- Two concurrent researchers; one critique revision; at most six proof attempts.
- Each model call has a 120-second workflow timeout. Embedded transport uses
  110 seconds, at most 20 calls including framework retries, and a configurable
  token ceiling (default 60,000). In-flight parallel requests may overshoot a
  token ceiling; it is not a dollar spending cap.
- Native WorkSwarm: enable SwarmFlow and explicitly configure the host's team
  token budget. Embedded adapter limits do not apply to the native host.
- No paper is treated as read in full when only an abstract was supplied.
- A critic's approval is advisory. Only the Lean subprocess can set proof
  verification, and a missing/unknown axiom audit fails closed.
- Missing literature: continue with uncited reasoning and record the outage.
- Missing Lean: return a candidate, never fabricate a checker success.
- All researchers fail or critique rejects the claim: return blocked findings.
- No provider credentials in script arguments, journals, or browser payloads.
- The current verifier supports ordinary Lean Std proofs with a conservative
  syntax policy. This policy is NOT an OS sandbox. Use this local hackathon
  setup only for trusted users; isolate Lean in a restricted container before
  exposing arbitrary theorem submissions publicly.
- No autonomous package installation or shell commands generated by agents.
